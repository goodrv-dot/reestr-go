# Службові скрипти (без персональних даних)

## merge_ne_v_roboti.py — зведення «Не беремо в роботу»
Зводить дві таблиці в один файл старого формату журналу 200 для імпорту:
- основа — лист «Не в роботі» (формат журналу 200 «сповіщення родин»);
- доповнення — лист «Аркуш2» (ПІБ трьома полями, Родич 1/2 з датою народження, адресою, контактами).

Що робить: прибирає колонку «Виконавець» (виконавців не підставляємо), ставить «Статус» = «Не беремо в роботу»,
для збігів (ПІБ) доповнює порожнє (родичі, телефони, адреси, дата/місце поховання), розбіжності — у примітку
та окремий звіт; нових загиблих з «Аркуш2» додає цілком; померлих родичів — лише в примітку. ІПН не переноситься.

    python3 -I merge_ne_v_roboti.py аркуш2.xlsx не_в_роботі.xlsx результат.xlsx розбіжності.xlsx

## dry_run_import.js — холостий прогін через справжній розбір імпорту
    node dry_run_import.js <тека_сайту> файл.xlsx <шлях_до_node_modules/xlsx>
Показує кількість карток, помилок і попереджень — до завантаження в базу.

## build-legacy.mjs — сумісність зі старими iPhone (Safari до iOS 14)

Сайт підключає скрипти через `boot.js`: нові браузери отримують звичайні файли, старі — копії з `legacy/`
(той самий код, переписаний старим синтаксисом). `polyfills.js` додає старим браузерам відсутні функції,
`vendor/dialog-polyfill-*` + `dialog-init.js` — вікна `<dialog>` для Safari до 15.4.

**Після кожної зміни будь-якого .js сайту і перед комітом:**

    npm i --no-save esbuild && node tools/build-legacy.mjs

Новий .js-файл — додати в список `APP` у `boot.js` (а не тегом `<script>` в index.html).
Перевірити старий режим у будь-якому браузері: відкрити сайт з `?legacy=1`.
